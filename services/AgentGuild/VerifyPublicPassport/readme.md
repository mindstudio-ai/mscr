# Verify Public Passport

Use this optional action for a counterparty's already public Agent Guild passport. Supply the complete credential object as JSON text, a separately chosen expected issuer DID, a separately chosen expected subject DID, and a simple output variable such as `passportEvidence`. Do not obtain the expected identities merely by copying untrusted credential fields; the handler checks equality but cannot establish independence of the caller's choices.

The field is multiline text because MSCR has no JSON-object field type. The handler parses it once for validation and rejects strings/arrays/null, duplicate keys, nonfinite numbers, excess nesting and oversized input. It sends the original validated JSON text without reserializing numbers, escapes or whitespace. A UTF-8 round-trip check rejects raw unpaired JavaScript surrogates before Fetch can replace them; ordinary escaped JSON text remains unchanged. Supported passports use `AgentGuildPassport`, Ed25519 `did:key` identities, `DataIntegrityProof`, `eddsa-jcs-2022`, `assertionMethod` and the matching issuer verification method.

Before transmission and again at completion, the handler checks the signed issuer/subject and UTC `validFrom`/`validUntil` fields. A passport must already be valid, not expired and issued within the last 24 hours. UTC dates use `Z` or `+00:00`; other date representations are unsupported. A missing, future, stale or mismatched passport produces a structured rejection, not registration or issuance. The remote verifier alone does not enforce this temporal policy.

The request posts only the original validated public credential JSON text to the free `https://agent-guild-5d5r.onrender.com/credentials/verify` route, without an invented envelope or added expected-identity fields. MindStudio's runtime receives the action inputs; Guild receives the public credential and logs a `passport_verified` event including unsuccessful verification. Never submit private credentials or claims. No workflow history, unrelated tool inputs, cookies or authentication headers are forwarded.

A completed response retains boolean `signatureValidReported` and `guildIssuedReported`, expected identity bindings and validity dates. `verified` is true only when both service flags are actual boolean true and all separate binding/time checks pass. Either false flag remains completed negative evidence with `verified: false`. A malformed, nonboolean or mismatched response is rejected. This is a report from the hosted Guild verifier, not independent local cryptographic verification.

A valid signature establishes origin and integrity, not truthful claims, task quality, safety, payment settlement or ownership of an endpoint. Verification does not authorize hiring, payment or subsequent workflow execution. Missing evidence never causes enrollment, issuance, API-key provisioning or payment. Those actions are absent from this connector.

Limits: 32 KiB credential text, 64 KiB decoded response body, no retry or redirect, and a 15-second fetch/body-read deadline. HTTP or transport problems return `status: unavailable`; input or evidence problems return `status: rejected`, both with a stable error code and `verified: false`. Invalid output variable names throw before network activity. Use a simple identifier of at most 64 characters; prototype-related names, dots and brackets are rejected.

Cancellation is requested at the deadline, but DNS, a remote verification or host work that ignores cancellation may continue. A timeout does not undo Guild logging. No fee or account is needed by these two Guild endpoints; MindStudio platform execution, authentication and connection onboarding are separate and not proven free by this connector's empty configuration. Tests exercise the actual native harness and compiled handler with HTTP substituted; no live verifier, hosted model, paid action or onboarding validation is claimed.
